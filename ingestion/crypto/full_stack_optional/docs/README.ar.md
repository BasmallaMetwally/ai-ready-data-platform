# دليل التشغيل بالعربي

ملخص سريع للمشروع وطريقة تشغيله. التوثيق الأساسي (اللي المفروض يقرأه صاحب العمل) موجود في `README.md` بالإنجليزي.

## المشروع بيعمل إيه؟

بايبلاين بيانات كامل بيسحب أسعار العملات الرقمية من Binance كل يوم، وبيعدّيها على أربع طبقات لحد ما تبقى جاهزة للتحليل:

1. **Bronze** — البيانات الخام زي ما هي، متخزنة كـ parquet في MinIO (بديل S3 محلي). مبنلمسهاش أبدًا، عشان لو قواعد الشغل اتغيرت نعيد المعالجة من هنا بدل ما نرجع للـ API تاني.
2. **Silver** — وظيفة Spark بتشيل التكرار، بتظبط الأنواع، وبتعزل الصفوف الغلط في مكان منفصل (مش بتحذفها).
3. **Gold** — PostgreSQL فيها star schema مبني بـ dbt: جدولين حقائق وجدولين أبعاد.
4. **العرض** — داشبورد Streamlit بيقرأ من الـ marts مباشرة.

كل ده متربوط بـ Airflow، وبيشتغل بأمر واحد.

## التشغيل

محتاجة Docker Desktop مع 8 جيجا رام على الأقل.

```bash
cp .env.example .env
make up
```

استني حوالي 3-5 دقايق أول مرة (بيبني الـ images)، بعدين:

- Airflow على `http://localhost:8080` — اليوزر `admin` والباسورد `admin`
- الداشبورد على `http://localhost:8501`
- MinIO على `http://localhost:9001`

بعد كده شغّلي البايبلاين:

```bash
make trigger                                 # تشغيلة واحدة كاملة
make backfill FROM=2024-01-01 TO=2026-09-01  # تحميل تاريخي متوازي
make dbt-test                                # الاختبارات
```

## مشكلة محتملة: Binance محجوب

`api.binance.com` بيرجّع خطأ 451 في بعض الدول (منها مصر أحيانًا). لو حصل كده، افتحي ملف `.env` وغيّري السطر ده:

```
BINANCE_BASE_URL=https://data-api.binance.vision
```

الدومين ده بتاع بيانات السوق بس — نفس الـ endpoints بالظبط ومن غير قيود جغرافية.

## أوامر مفيدة

| الأمر | بيعمل إيه |

| `make ps` | حالة الخدمات |
| `make logs` | اللوجات كلها |
| `make psql` | تفتحي psql على قاعدة البيانات |
| `make test` | اختبارات بايثون (سريعة، من غير نت) |
| `make dbt-docs` | توثيق dbt تفاعلي |
| `make down` | إيقاف من غير مسح البيانات |
| `make nuke` | إيقاف ومسح كل حاجة |

## نصايح للبورتفوليو

- حطي سكرين شوتس للـ Airflow graph view والداشبورد في فولدر `docs/images/` واربطيها في الـ README.
- شغلي `make dbt-docs` وارفعي الناتج على GitHub Pages — بيبان احترافي جدًا.
- في الانترفيو، الأسئلة المتوقعة هتكون عن الـ idempotency وليه اخترتي SCD2 وليه `fct_asset_metrics_daily` full rebuild مش incremental. الإجابات كلها مشروحة في قسم "Engineering decisions" في الـ README.

## تحديث الإصدار 2

اتعمل جولة تطوير كاملة، ملخصها في `CHANGELOG.md`. أهم حاجة فيها إن فيه **5 أخطاء حقيقية** اتلقت في كود الإصدار الأول، منها 4 كانوا بيطلّعوا أرقام *تبان صح* من غير ما يرموا أي error — وده النوع الغالي من الأخطاء.

أخطر واحد فيهم كان في الـ SCD2 بتاع `dim_asset`: كنت بحسب `lead()` قبل ما أشيل الـ snapshots المكررة، فكل نسخة كانت بتقفل على snapshot اتشال — يعني فجوات في الخط الزمني، وأي fact بيقع في الفجوة دي مكانش بيلاقي صف مقابل في الـ dimension.

كمان اتضاف:
- طبقة HTTP فيها rate limiter و circuit breaker
- نظام audit وتنبيهات فعلي (الإصدار الأول كان بيعمل الجدول ومش بيكتب فيه!)
- كشف شذوذ إحصائي (بيقارن كل تشغيلة بمتوسط آخر 30)
- Airflow Datasets بدل الجدولة الزمنية
- Data contracts مفروضة على جدول الحقائق
- الاختبارات من 17 لـ 47

**ملف `docs/interview_prep.md`** فيه الأسئلة المتوقعة في الانترفيو وإجاباتها مربوطة بالكود — اقريه كويس قبل أي مقابلة.
